# Часть 2 - форма входа с инфраструктурой

Взял форму из первой части и добавил TypeScript, сборку, проверку кода и тесты. Вся логика находится в `src/index.ts`.

## Как запустить

Нужны Node.js и npm. Версия Node записана в `.nvmrc` - `24.22.3`, npm нужен версии 11 или новее.

На Linux или macOS с установленным nvm:

```
cd with-infrastructure
nvm install
nvm use
npm ci
npm run serve
```

После запуска открыть адрес из терминала, обычно http://localhost:5173. Чтобы остановить сервер, нажать Ctrl+C.

На Windows с nvm-windows сначала выполнить `nvm install 24.22.3` и `nvm use 24.22.3`, затем в папке `with-infrastructure` выполнить `npm ci` и `npm run serve`.

Просто открыть HTML двойным кликом здесь не получится, потому что TypeScript нужно сначала преобразовать в JavaScript.

Для входа:

- телефон: `+79991234567` или `89991234567`;
- пароль: `dodo1234`.

Сервера нет, данные для входа записаны прямо в коде. MAX и VK пока только выводят сообщение.

## ❓ Почему npm

Выбрал npm, потому что он уже устанавливается вместе с Node.js. В `package-lock.json` сохраняются версии библиотек, а `npm ci` устанавливает именно их.

Версию Node зафиксировал в `.nvmrc`, чтобы через nvm можно было выбрать ту же версию на другом компьютере. В `engines` файла `package.json` также указал минимальные версии Node и npm.

## ❓ Настройки TypeScript

Включил строгие проверки, чтобы находить больше ошибок до запуска сайта:

- `strict` проверяет типы строже и заставляет учитывать `null`;
- `noUncheckedIndexedAccess` напоминает, что элемента по индексу может не быть;
- `exactOptionalPropertyTypes` различает отсутствующее свойство и `undefined`;
- `noUnusedLocals` и `noUnusedParameters` находят неиспользуемые переменные и параметры;
- `noImplicitReturns` помогает заметить пропущенный `return`, а `noFallthroughCasesInSwitch` - забытый выход из ветки `switch`.

`ES2022` выбрал для современных браузеров. Типы DOM нужны для работы с полями и кнопками. `ESNext` и `Bundler` использую для модулей, которые собирает Vite.

`noEmit` нужен, чтобы TypeScript только проверял код, а готовые JS-файлы создавал Vite. Остальные настройки проверяют импорты и совместимость кода со сборщиком. `skipLibCheck` пропускает проверку файлов типов самих библиотек. В `include` указаны наши файлы, а папка сборки исключена.

В `index.ts` есть тип `LoginData` с телефоном и паролем. Оба поля - строки. `MessageType` задаёт два варианта сообщения: ошибка или успех. У функций указаны типы параметров и результата. Элементы страницы проверяю через `instanceof`, чтобы не обращаться к полю, которого нет.

## ❓ Почему Vite

Выбрал Vite, потому что с ним легко запустить сайт и собрать TypeScript, стили и картинки. Для этой формы отдельные настройки сборки не понадобились. В командах указана папка `src`, потому что там лежит HTML.

Перед сборкой запускается проверка типов: сам Vite только преобразует TypeScript в JavaScript. Готовые файлы попадают в `src/dist`. Эта папка не добавляется в Git и не проверяется линтером.

## ❓ Настройки ESLint

Взял рекомендованные правила `@eslint/js` и `typescript-eslint`, чтобы не писать всё с нуля. Они находят такие проблемы, как неиспользуемые переменные и явный `any`.

Для кода формы указал браузерные переменные, например `document`, а для файлов настроек - переменные Node.js. Оформление кода оставил Prettier.

## ❓ Настройки Prettier

Выбрал Prettier, чтобы не поправлять отступы вручную. Он форматирует TypeScript, HTML, CSS и README. Дополнительные плагины для этих файлов не нужны.

Поставил два пробела, одинарные кавычки, точки с запятой и запятые в конце многострочных списков. Ширина строки - 100 символов. Переводы строк LF нужны, чтобы оформление было одинаковым на Windows и Linux.

## ❓ Почему Vitest и такие настройки тестов

Выбрал Vitest, потому что он работает с Vite и TypeScript. В настройках указал `jsdom`, чтобы в тестах можно было работать с формой и `localStorage` без открытия браузера. Адрес `http://localhost/` нужен для работы хранилища в тестах.

Все тесты находятся в `src/index.test.ts`. Они проверяют телефон, длину пароля, правильный и неправильный вход, сообщения, кнопки соцсетей и запоминание телефона. Ещё проверяется, что форма работает при запрете хранилища.

Перед каждым тестом формы очищаю хранилище и заново создаю разметку. Для анимации ошибки использую тестовые таймеры, чтобы не ждать её окончания. Внешний вид всё равно нужно смотреть в браузере.

## Как работает запоминание

Если поставить галочку и правильно войти, в `localStorage` сохранится только телефон. После перезагрузки он подставится в поле. Пароль не сохраняется. При входе без галочки сохранённый телефон удаляется.

Объяснения вёрстки, доступности и брейкпоинтов есть в [README первой части](../native/README.md).
