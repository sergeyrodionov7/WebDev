# Часть 1 - нативные технологии

Форма входа в стиле Додо Пиццы на чистом HTML, CSS и JS без библиотек.

## Как запустить

Просто открыть `index.html` в браузере (двойной клик). Ничего ставить не надо.

Данные для входа:
- телефон: `+7 (999) 123-45-67` (можно и с 8)
- пароль: `dodo1234`

## ❓ Доступность

- у `html` стоит `lang="ru"`, чтобы скринридер читал по-русски
- у полей есть `label` с `for`, а не только placeholder (placeholder пропадает когда начинаешь писать)
- галочка обёрнута в `label`, поэтому можно кликать по тексту
- фоновое видео и иконка крестика скрыты от скринридера через `aria-hidden="true"`, у логотипа нормальный `alt`
- блок с сообщениями `aria-live="polite"` - скринридер сам зачитает ошибку
- `autocomplete` у полей, чтобы работало автозаполнение и менеджеры паролей
- `:focus-visible` - видно где фокус, если ходить по форме Tab'ом. Форму можно пройти вообще без мыши
- кнопки это `button`, а не `div`, поэтому нажимаются с клавиатуры
- семантические теги `header`, `main`, `section`, `form`, `footer`

## ❓ Подход к вёрстке

Использовал flex. У меня везде раскладка в одну линию: карточка - это колонка элементов, строка с логотипом и крестиком - ряд, кнопки MAX/VK - ряд. Для такого flex самое то, через него легко центрировать карточку и делать отступы через `gap`. Grid нужен когда двумерная сетка (строки и столбцы сразу), тут такого нет. Блочная вёрстка тоже бы сработала, но центрировать и ставить элементы в ряд через неё неудобно (margin auto, float и т.д.).

## ❓ Брейкпоинты

- `800px` - планшеты и узкие окна, уменьшаю заголовок и отступы
- `500px` - телефоны (большинство телефонов 360-430px в ширину), тут кнопки MAX/VK встают друг под другом, иначе текст не влезает, и шрифты меньше

Больше 800 - обычный компьютер, карточка там всё равно фиксированной ширины 440px, так что отдельный брейкпоинт не нужен.

## ❓ Хранение данных

Выбрал `localStorage`, потому что данные остаются после закрытия браузера, а это и есть "запомнить меня". `sessionStorage` очищается при закрытии вкладки, а cookie отправляются на сервер с каждым запросом, а сервера у меня нет.

Пароль я **не сохраняю**, только телефон. `localStorage` это просто текст, его видно в DevTools и любой скрипт на странице может его прочитать, так что хранить там пароль небезопасно. В нормальном проекте сервер бы выдавал токен и хранил его в httpOnly cookie.

## ❓ Стрелочные vs именованные функции

Использовал и те и те. Именованные (`validatePhone`, `showMessage`, `onLogin`) - для основной логики, их удобно вызывать по имени и они нормально видны в ошибках в консоли. Стрелочные - в обработчиках кнопок и в `setTimeout`, там короче писать.

Больше понравились стрелочные, они компактнее, особенно для маленьких функций типа `validatePassword`. Но для больших кусков именованные читаются понятнее.

## Что где

Селекторы:
- по классу - `.card`, `.btn` и т.д.
- по тегу - `body`, `h1`, `p`, `.hero video`
- по id - `#login-title`
- по атрибуту - `input[type="checkbox"]`
- псевдоклассы - `:hover`, `:active`, `:focus`, `:focus-visible`, `:user-invalid`, `:empty`

Анимации:
- transition - смена цвета у кнопок и полей
- keyframes - `shake`, поле трясётся при неверном вводе

JS: валидация телефона и пароля, сообщения пользователю, проверка с захардкоженными данными, запоминание телефона в localStorage.
